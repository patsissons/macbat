See where your MacBook’s power goes

macbat is a terminal power monitor for Apple Silicon laptops. It shows what the charger is delivering, what the system is drawing, and whether the battery is charging or covering the shortfall. It updates every second and never asks for sudo.

Install View on GitHub

What it shows

Four live panels and a history chart, laid out like macmon: the name on the left of each border, the live value on the right, and the details along the bottom.

Power in

Watts, volts and amps arriving at the USB-C or MagSafe port, and how much of the charger’s negotiated power you’re using.

System draw

Whole-system power with its average and peak. When the charger can’t keep up and the battery covers the difference, it says by how much.

Battery

Signed charge or discharge power, pack voltage and current, and the time until full or empty.

Charge

Charge level, mAh remaining, capacity compared with the design capacity, cycle count and pack temperature.

Power history

Power in, system and battery on one chart over the last 1, 5, 15 or 60 minutes, plus the energy each has used since start.

Charger details

The power your Mac negotiated with the charger, the levels the charger offers, and a note when a standard 3 A cable is holding back a bigger charger.

Why macbat?

macOS already knows all of this, but it’s spread across tools that need root, update slowly, or only show a percentage.

No sudo

Reads the SMC sensors and the battery’s registry entry as a normal user, so there’s nothing to elevate and nothing running as root.

Live numbers

The battery driver’s own power figures only refresh every 30 to 60 seconds. macbat reads sensors that update about once a second.

Scriptable

macbat pipe prints one JSON sample per line, ready for jq, a log file or your own dashboard.

One small binary

A single 1.2 MB Rust binary with no daemon, no background service and nothing to configure.

Install

Install with Homebrew, or build it yourself with Cargo.

  • A MacBook with Apple silicon (M1 or later)
  • macOS

With Homebrew

Installs the latest release from the patsissons/tap tap. Homebrew builds it from the release source and installs Rust for the build if needed.

$ brew install patsissons/tap/macbat

With Cargo

Needs Rust, from rustup.rs. Builds the latest version from GitHub and puts macbat in ~/.cargo/bin.

$ cargo install --git https://github.com/patsissons/macbat

From a clone

Also needs Rust. Builds a release binary and installs it to ~/.local/bin. Set BINDIR to install somewhere else.

$ git clone https://github.com/patsissons/macbat
$ cd macbat
$ scripts/install.sh

Usage

Run macbat for the dashboard, or use a subcommand to get the data as text.

$ macbat                 # dashboard
$ macbat -i 500          # dashboard, sampling every 500 ms
$ macbat pipe            # JSON lines, one sample per interval
$ macbat pipe -s 1 | jq  # a single sample
$ macbat debug           # raw SMC keys and the battery registry entry
$ macbat debug P         # every SMC key starting with "P"
  • q quit
  • c cycle the accent color
  • v switch between sparklines and gauges
  • r sparkline scale: default, auto (with a ceiling line) or full
  • + - history window: 1, 5, 15 or 60 minutes

Your choices are saved in ~/.config/macbat.json.

Where the numbers come from

Live power comes from the SMC, the chip that manages power and sensors. Charger, capacity and time estimates come from the battery’s IORegistry entry, the same data ioreg shows.

MetricSourceNotes
Power inSMC PDTR, VD0R, ID0RPower after the USB-C or MagSafe port, about once a second
SystemSMC PSTRWhole-system draw, the same value macmon reports
BatterySMC B0AV × B0ACPositive while charging, negative while discharging; checked against the registry voltage
Battery temperatureSMC TB0T–TB2TAverage of the pack sensors
Charger, charge, capacity, cycles, time leftIORegistry AppleSmartBatteryAlso the fallback for power when the SMC can’t be read

Good to know

Why does my 70 W charger show 60 W?

The header shows the power your Mac and the charger agreed on over USB-C, not the number printed on the charger. A charger can only offer more than 3 A when the cable is rated for 5 A, so a 70 W charger on a standard USB-C cable tops out at 20 V × 3 A = 60 W. macbat adds “3 A cable limit” to the header when it sees this.

Dual-port chargers often offer less than their label on each port, and some never offer their full rating over USB-C.

Is “% of design” my battery health?

Not exactly. It’s the battery’s nominal capacity divided by its design capacity. The “Maximum Capacity” in System Settings uses Apple’s own formula, which isn’t published, so the two can differ by a few percent.

Why doesn’t power in equal system plus battery?

The sensors are read at slightly different moments, so during load spikes a single sample can be off by a watt or two. The averages in the history panel line up.

Does it work on Mac desktops or Intel Macs?

macbat is built for Apple silicon laptops. Desktops have no battery, and Intel Macs use different sensors.
